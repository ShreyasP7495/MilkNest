MilkNest — Low Level Design (LLD)
1. Overview
This document defines the low-level system design for MilkNest MVP, including:
	•	Service-level architecture
	•	Class/module structure (Golang backend)
	•	Database access layer design
	•	Core business logic implementation
	•	Background jobs and schedulers
	•	Sequence flows
	•	Error handling strategy

2. Backend Architecture Style
We will use a modular monolith (MVP stage) in Golang.
Why Modular Monolith?
	•	Faster development
	•	Easier debugging
	•	Lower infrastructure cost
	•	Can be split into microservices later

4. Layered Architecture (Per Module)
Each module follows 4 layers:
1. Handler Layer (HTTP)
	•	Input validation
	•	Request parsing
	•	Response formatting
2. Service Layer (Business Logic)
	•	Core logic
	•	Validation rules
	•	Transactions
3. Repository Layer (DB Access)
	•	SQL queries
	•	ORM or raw SQL
4. Model Layer (Structs)
	•	DB models
	•	DTOs

Rule Enforcement
	•	Max 10 packets/day per household
Implementation
type SubscriptionService struct {     repo SubscriptionRepository     inventoryRepo InventoryRepository }  func (s *SubscriptionService) CreateSubscription(req CreateSubscriptionRequest) error {      total := req.Quantity * estimateDays(req.Frequency)      if req.Quantity > 10 {         return errors.New("max 10 packets per day allowed")     }      // 1. Save subscription     sub := Subscription{...}     s.repo.Save(sub)      // 2. Reserve inventory     s.inventoryRepo.Reserve(req.ProductID, total)      return nil }

7. Order Generation Engine (CRON JOB)
Runs Daily at 12:00 AM
Flow
Subscriptions → Active Users → Generate Orders → Save Orders
Implementation
func GenerateDailyOrders() {     subs := subscriptionRepo.GetActiveSubscriptions()      for _, sub := range subs {         order := Order{             SubscriptionID: sub.ID,             DeliveryDate: time.Now().Add(24 * time.Hour),             Quantity: sub.Quantity,             Status: "pending",         }          orderRepo.Save(order)     } }

8. Inventory Reservation Logic
Problem
Avoid overbooking milk stock.
Solution
	•	Reserve inventory at subscription creation
	•	Deduct inventory at order generation
func Reserve(productID string, qty int) error {     current := db.GetStock(productID)      if current < qty {         return errors.New("insufficient stock")     }      db.UpdateStock(productID, current-qty)      return nil }

func HandlePaymentWebhook(event PaymentEvent) {     if event.Status == "success" {         orderRepo.MarkPaid(event.OrderID)     } }

12. Offer Engine
Rule
	•	50 packets → 2 free
	•	100 packets → 5 free
func CalculateOffer(packets int) int {     if packets >= 100 {         return 5     }     if packets >= 50 {         return 2     }     return 0 }

15. API Handler Example
func (h *SubscriptionHandler) Create(w http.ResponseWriter, r *http.Request) {      var req CreateSubscriptionRequest     json.NewDecoder(r.Body).Decode(&req)      err := h.service.CreateSubscription(req)      if err != nil {         http.Error(w, err.Error(), 400)         return     }      json.NewEncoder(w).Encode("success") }

Data Flow Summary
	•	Customer places subscription via Mobile/Web App
	•	Subscription Service validates and stores data
	•	Inventory Service reserves stock
	•	Order Service generates daily orders via cron job
	•	Delivery Service assigns delivery partners
	•	GPS updates stored in Redis
	•	Notification Service sends updates to user
	•	Payment Service handles Razorpay + BNPL flows
	•	Support Service handles complaints and chat

21. Summary
MilkNest LLD focuses on:
	•	Modular backend design in Golang
	•	Strong subscription + inventory consistency
	•	Daily order generation system
	•	Real-time delivery tracking
	•	Scalable payment and notification system
This design is optimized for MVP execution with a clear path to microservices scaling.
